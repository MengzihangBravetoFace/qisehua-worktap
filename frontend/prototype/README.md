# 待办规则说明（基于当前原型实现）

> 本文只描述 `index.html` 里真实存在的行为，不补写需求文档中的设想。代码与文档不一致处，以代码为准并单独标注。
> 数据都在前端内存里（`DATA.tasks` 等），刷新页面即恢复初始状态；`TODAY` 固定为 `2026-11-23`。

## 1. 待办有哪些来源

### 1.1 初始种子数据（4 条，写在 `DATA.tasks`）

| ID | 内容 | 关联捐赠人 | 来源标签 | 截止 | 负责人 | overdue 标记 |
| --- | --- | --- | --- | --- | --- | --- |
| t1 | 90 天未互动：电话问候并了解今年物资计划 | 郑州明远建设（d2） | 自动规则（90 天未互动） | 2026-11-23 | 吴冲 | false |
| t2 | 提交 2026 年融合教师培训项目结项材料 | 河南同心教育基金会（d3） | 承诺事项 | 2026-11-20 | 吴冲 | true |
| t3 | 发送绘本到位照片与一句话回馈 | 李静（d1） | 捐赠回馈 | 2026-11-24 | 顾佳怡 | false |
| t4 | 邀请张敏参加 12 月教师督导 | 张敏（d4） | 手动创建 | 2026-11-27 | 顾佳怡 | false |

注意：这些“自动规则 / 承诺事项 / 捐赠回馈”只是**来源标签**，原型没有在运行时按规则生成它们，是预先写死的数据。

### 1.2 运行时真正会新增的待办（只有两种）

**A. 手动新建**
入口：待办与提醒页「＋ 新建待办」；捐赠人详情页「＋ 待办」。
- 字段：关联捐赠人（下拉，默认 d1 或当前捐赠人）、待办内容（必填）、截止日期（文本框，默认 `2026-11-27`，无格式校验）、执行人（下拉：吴冲 / 顾佳怡）。
- 保存后：写入数组最前面，`source = 手动创建`，`status = 待处理`，`overdue = false`，并写一条操作留痕。
- 只有“待办内容”为空时会报错拦截，其他字段不校验。

**B. AI 记录确认保存**
入口：捐赠人详情「记一笔（AI）」→「AI 解析」→「确认并保存」。
- 每次确认保存都会**固定新增一条**待办：
  - 标题：`跟进：12 月中旬户外玩具捐赠`
  - 截止：`2026-12-15`（固定值，与输入文本无关）
  - 负责人：`吴冲`（固定）
  - 来源：`AI 记录生成`，`overdue = false`
- 同时向时间线写一条 AI 草稿记录，并写操作留痕。
- 没有去重：同一捐赠人反复保存会生成多条同名待办。
- 无论当前打开的是哪个捐赠人，正文文案都是同一段示例文本。

### 1.3 只在页面上“提示”、但不会生成待办的东西

- **90 天未联系**：`daysSince(lastContact) >= 90` 只用于两处展示——首页统计卡的「90 天未联系」数量、捐赠人列表/详情里的「N 天未联系」标签；**不会自动创建待办**（t1 是种子数据）。
- **承诺事项**：时间线条目里的 `promise` 与 `overdue` 只是展示标记（t2 的逾期是写死的 true），**没有到期判断，也不会自动生成待办**。
- **待回馈捐赠**：首页统计卡统计 `feedback !== '已回馈'` 的捐赠条数，**不会自动生成回馈待办**（t3 是种子数据）。
- **未到账认领**：心愿单页有列表和「未到账不可标已回馈」的拦截，但同样不生成待办。

## 2. 紧迫性 / 排序规则

- **是否逾期**：只看每条待办自己的 `overdue` 布尔值，**不与 `TODAY`、截止日期做任何比较**。目前只有 t2 初始为 `true`；新建待办、AI 生成的待办都是 `false`；完成待办时会被置为 `false`。因此到期了也不会自动变成“已逾期”。
- **待办与提醒页**：先按 `overdue` 降序排序（逾期在前），其余保持数组顺序（新待办插在最前）；**不按截止日期排序**，也没有「今日 / 本周 / 全部」分组或筛选。
- **首页「今日待办」**：取所有未完成待办，按数组顺序展示，**不按截止日期过滤**——“今日”只是标题文案。
- **捐赠人详情「待办」页签**：展示该捐赠人的全部待办（含已完成），数组顺序。
- **其它入口**：侧边栏没有数量角标，没有消息 / 邮件 / 站内提醒。
- 首页统计卡「逾期承诺」统计的是**未完成且 overdue=true 的待办数量**，不是承诺条目数。

## 3. 生成后展示在哪

1. 工作台首页 → 「今日待办」列表（仅未完成）。
2. 待办与提醒页 → 进行中列表 + 下方「已完成」区块。
3. 捐赠人详情 → 「待办」页签（该捐赠人的全部待办）。
4. 首页统计卡：「90 天未联系」「逾期承诺」为派生数量，本身不可点击进入筛选。

## 4. 怎么完成 / 消除

- 点击待办左侧勾选按钮或右侧「完成」，打开「完成待办」弹窗：
  - 「回填结果」文本框：**非必填**。
  - 「同时生成一条互动记录」复选框：**默认勾选**，但只有回填结果非空时才会真正写入时间线（代码条件为 `checked && result`）。
  - 确认后：`status = 已完成`、`overdue = false`，写一条「完成待办」操作留痕，页面刷新。
- 完成后：从首页「今日待办」消失；在待办页进入「已完成」区块；在详情页仍以划线样式显示，按钮变成「已回填」。
- **没有**删除、取消、延后（snooze）、编辑、重新打开、批量完成；完成即终态。
- 完成待办**不会**更新捐赠人的 `lastContact`，也**不会**关闭时间线里的承诺或改变捐赠回馈状态。因此「90 天未联系」标签和首页统计不会因为完成待办而变化；`lastContact` 在整个原型中没有任何赋值逻辑。

## 5. 尚未实现或有歧义的地方

1. **90 天自动生成待办未实现**：只有视觉标记和统计，没有定时扫描或页面加载时生成。需求文档写“连续 90 天无互动自动生成联系待办”，原型只做到标签级别。
2. **承诺事项逾期提醒未实现**：`overdue` 是静态字段，没有任何“截止日期 < 今天”的判断；AI 记录里提取的承诺固定 `overdue=false`，即使文本写“12 月中旬”也不会在过期后自动标红。
3. **回馈待办未自动生成**：t3 是种子数据；而且与数据自相矛盾——李静那笔绘本（n1）已是「已回馈」，T3 却仍是待处理。
4. **“今日待办”名不符实**：没有按截止日期筛选今天，未来日期的待办也会出现在首页。
5. **逾期状态不会自动变化**：过了截止日期，列表仍显示“截止 2026-11-20”而没有「已逾期」标记，除非数据里预先写了 `overdue=true`。
6. **无待办去重 / 合并**：需求文档提到“重复待办合并”，原型没有任何判重；重复保存 AI 记录会叠加多条。
7. **无负责人筛选、捐赠人筛选、关键词搜索、分页**。
8. **待办与互动记录是两套数据**：完成时写时间线只是附加动作，二者没有双向关联（时间线不记录来源待办 ID）。
9. **无提醒通道**：没有站内红点、没有推送/邮件/飞书消息。
10. **ID 可能重复**：运行时新建待办用 `'t' + (Date.now() % 100000)`，同一毫秒内多次创建理论上会撞 ID。
11. **时间字段不真实**：`TODAY`、留痕时间（如 `2026-11-23 13:36`）、AI 记录日期（`2026-11-21`）都是硬编码，不随系统时间变化。
12. **权限未接入待办操作**：登录演示只区分机构工作人员与外部人员，外部人员根本进不了管理端；管理端内部对待办的增删改没有做角色校验。
13. **数据不持久化**：所有新增/完成操作只在内存中生效，刷新即还原。
14. **文档中的“任务智能体”“待办分配协作”等未实现**：原型只有单一负责人字段和固定两名执行人可选。
