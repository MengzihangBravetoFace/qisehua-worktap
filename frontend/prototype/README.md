# 奇色花 · 捐赠人关系维护工作台原型说明

> 本文按「整体结构 → 各部分功能 → 已知问题」组织，描述对象是 `index.html` 的**实际实现**，不是需求设想。
> 单文件、零依赖、双击即可在浏览器打开；所有数据都在前端内存中，刷新即恢复初始状态；`TODAY` 固定为 `2026-11-23`，不接后端、不接真实数据库或 AI。
> 与需求文档不一致或文档未明确的地方，以本文标注的“当前实现”为准。

## 一、页面整体结构

原型由三块组成：

| 部分 | 入口 | 说明 |
| --- | --- | --- |
| 登录页 | 打开页面默认显示 | 手机号或身份证号 + 身份选择，做界面与校验演示 |
| 管理端 | 机构工作人员登录后 | 7 个板块：工作台首页、捐赠人档案、数据导入、待办与提醒、物资与心愿单、分析视图、权限与账号 |
| 捐赠人门户 | 外部人员登录后（全屏，无管理端侧栏） | 本人捐赠与物资去向、支持意向、回馈与报告、申请绑定 |

管理端顶部另有「演示导览」，按「导入 → 记录 → 时间线 → 待办」四步串起主链路。

## 二、登录与账号

### 2.1 登录页

- 身份切换：**机构工作人员 / 外部人员**。
- 单一输入框同时支持 **11 位手机号**或 **18 位身份证号**，自动识别并在登录后脱敏展示。
- 校验规则（前端演示）：
  - 空值 →「请输入手机号或身份证号。」
  - 格式不符 →「格式不正确：请输入 11 位手机号或 18 位身份证号。」
  - 号码绑定的是另一身份 → 提示切换身份后重试。
  - 号码未绑定 →「该号码未绑定账号，请联系管理员开通（演示）。」
- 演示账号：
  - 机构工作人员：`13800001234` 或身份证号 `410105199001011234`
  - 外部人员：`13900005678`
- 支持「一键填充当前身份的演示账号」。

### 2.2 身份分流与绑定关系

| 身份 | 登录后 | 账号绑定 |
| --- | --- | --- |
| 机构工作人员 | 完整管理端（工作台首页），侧栏显示姓名与「退出」 | 写死为吴冲 |
| 外部人员 | 全屏捐赠人门户，仅本人数据 | 写死为 王海涛 · 郑州明远建设有限公司（d2） |

- 绑定关系写在前端常量里，没有真实账号系统、没有邀请链接、没有注册/找回密码。
- 外部人员登录后看不到管理端导航，也没有任何进入管理端的入口；退出后回到登录页。

### 2.3 登录态与退出

- 页面初始为未登录状态，必须先登录才能进入任何界面。
- 退出入口：管理端侧栏底部「退出」、权限页「退出登录」、外部门户顶栏「退出登录」。
- 退出后清空登录态与支持意向提交状态，重新回到登录页。

## 三、管理端

### 3.1 工作台首页

- 四张统计卡：捐赠人档案数、90 天未联系数、逾期承诺数、待回馈捐赠数。
- 「今日待办」：列出**所有未完成待办**（不按截止日期过滤），可跳转全部待办。
- 「核心链路」：导入 → 一句话记录 → 时间线 → 待办，各步带跳转入口。
- 「最近操作留痕」：展示审计记录，可跳转权限与账号。
- 统计口径：90 天未联系按 `daysSince(lastContact) >= 90`；逾期承诺按未完成且 `overdue=true` 的待办数；待回馈按 `feedback !== '已回馈'` 的捐赠条数。

### 3.2 捐赠人档案

- 列表字段：名称/单位、资源类型、联系人·职务、来源介绍人、最近互动、负责人、状态。
- 搜索：名称 / 联系人 / 来源介绍人 / 职务；类型筛选：全部、基金会、爱心企业、爱心个人、学者。
- 状态标签：最近联系 ≥ 90 天显示「N 天未联系」，否则「正常」。
- 新建档案：
  - 名称/单位与联系人为**必填**，其余可空（空值落为“待补充/未填写”）。
  - 名称命中「教育厅 / 教育局 / 政府 / 教科文组织 / 民政 / 管委会」时**整条拦截**，弹窗提示并生成拒收记录（F-12，宁严不宽）。
  - 同名档案只**提示建议合并**，不阻断保存。
  - 创建后写入建档时间线、操作留痕，并进入详情页。

### 3.3 捐赠人详情

- 顶部：类型、负责人、最近互动、状态标签；操作「记一笔（AI）」「编辑档案」「＋ 待办」。
- 信息区：手机（脱敏展示）、来源介绍人、行业、捐赠方式、地区、备注。
- 历史职务：以标签形式保留旧职务，不覆盖。
- 三个页签：
  - **互动时间线**：记录类型、日期、记录人；AI 记录带「AI 草稿 · 人工确认」标记，系统动作带「系统留痕」；承诺事项单独展示，逾期时标红（逾期为数据字段，不是实时计算）。
  - **捐赠与去向**：日期、类型、内容、去向/用途、回馈状态；可「标记已回馈」。**物资未到账时禁止标记已回馈**（F-04）。
  - **待办**：该捐赠人的全部待办（含已完成）。
- AI「记一笔」：输入自然语言 → 生成结构化草稿供人工核对 → 确认保存后写入时间线、生成一条待办并留痕；不会自动保存。
- 编辑档案：修改当前职务时，旧职务自动写入历史职务并生成变更留痕。

### 3.4 数据导入

- 上传区为**静态示例**：「捐赠人信息一览表（脱敏示意）.xlsx · 14 行 · 8 列」，不真正读取文件。
- 「自动映射」把未匹配列默认填为「备注（沟通摘要）」并清除待映射状态。
- 导入前有 1 列未映射时，点「开始导入」会被拦截并提示先完成映射。
- 校验结果：12 行可导入、1 行拒收（河南省教育厅，政府类整行不入库）、未映射时另 1 行待确认。
- 映射完成后点「开始导入」只弹出结果弹窗（12 成功 / 1 拒收 / 1 待人工处理），**不会真的写入档案数据**。
- 页面标注单次上限 500 行，但未做实际行数校验。

### 3.5 待办与提醒

- 进行中列表 + 已完成区块；逾期项排在前面。
- 新建待办、完成待办、关联捐赠人等交互详见第四章。
- 页面顶部写有自动规则文案，但原型并未真正按规则生成待办（见 4.5 与第六章）。

### 3.6 物资与心愿单

- 心愿单列表 4 条：绘本（图书角补充）、户外感统器材、美术材料包、午睡床品；展示已筹/目标、进度条、状态。
- 每条可点名称或「查看详情」进入**心愿单详情**：
  - 手写 SVG 环形图展示各捐赠人占比（按认领数量，含未到账），带图例、数量与百分比。
  - 概况卡：认领合计、捐赠人数、未到账笔数、剩余缺口。
  - 明细表：捐赠人（可跳档案）、捐赠日期、物品名称、数量、状态、去向/备注；图表与表格同源，数量一致。
- 「登记认领」：数量必须大于 0 且不超过剩余缺口；提交后累加进度、写入该心愿单的捐赠记录、生成一条「未到账」捐赠并进入未到账列表；完成后状态变「已完成」。
- 「未到账认领」列表：列出 `feedback='未到账'` 的捐赠，提示到账前不得标记已回馈。
- 数据口径：心愿单占比与进度按“认领”计算，未到账也计入；这与“已到账”不是同一口径，页面已标注。

### 3.7 分析视图

- **资源类型分布**：按档案类型聚合的条形图（动态计算）。
- **互动频次**：30 天内 / 31–90 天 / 90 天以上三档（动态计算）。
- **候选维护建议**：3 条**写死的示例文案**，带“依据”片段；其中星火社区服务中心标注「依据不足」。
- 页面标注 P1、仅聚合视图，不启用 AI 结论。

### 3.8 权限与账号

- 「当前登录身份」：姓名、身份、登录方式、脱敏号码、退出登录。
- 「角色与模块权限」：按 6 个模块分组（档案、导入、待办、物资心愿单、分析、权限账号）：
  - 机构工作人员：绿色 ✓ 能力标签，本期全部放开；
  - 外部人员：统一「待定」，不设细规则。
- 「账号与实名状态」：姓名、角色、实名状态、可见范围、状态；标注未实名不得上传信息。
- 「操作留痕」：时间、操作人、对象、动作、说明。
- 第三版已移除原「脱敏与合规边界」板块；但建档与导入中的政府类拦截仍在执行（见 3.2 / 3.4）。

## 四、待办规则（当前实现）

### 4.1 待办来源

**初始种子数据（4 条，写在 `DATA.tasks`）**

| ID | 内容 | 关联捐赠人 | 来源标签 | 截止 | 负责人 | overdue |
| --- | --- | --- | --- | --- | --- | --- |
| t1 | 90 天未互动：电话问候并了解今年物资计划 | 郑州明远建设（d2） | 自动规则（90 天未互动） | 2026-11-23 | 吴冲 | false |
| t2 | 提交 2026 年融合教师培训项目结项材料 | 河南同心教育基金会（d3） | 承诺事项 | 2026-11-20 | 吴冲 | true |
| t3 | 发送绘本到位照片与一句话回馈 | 李静（d1） | 捐赠回馈 | 2026-11-24 | 顾佳怡 | false |
| t4 | 邀请张敏参加 12 月教师督导 | 张敏（d4） | 手动创建 | 2026-11-27 | 顾佳怡 | false |

来源标签只是标签，原型不会在运行时按这些规则自动生成待办。

**运行时真正会新增的待办只有两种**

1. **手动新建**（待办页「＋ 新建待办」、捐赠人详情「＋ 待办」）
   - 字段：关联捐赠人、待办内容（必填）、截止日期（文本，默认 `2026-11-27`，无格式校验）、执行人（吴冲 / 顾佳怡）。
   - 保存后插到数组最前，`source=手动创建`、`status=待处理`、`overdue=false`，并写操作留痕。
2. **AI 记录确认保存**
   - 每次确认保存固定新增一条：「跟进：12 月中旬户外玩具捐赠」，截止固定 `2026-12-15`、负责人固定吴冲、来源「AI 记录生成」。
   - 不去重，重复保存会叠加多条。

### 4.2 哪些情况不会生成待办

- **90 天未联系**：只用于首页统计和档案上的「N 天未联系」标签，不自动创建待办。
- **承诺事项**：时间线里的承诺与「已逾期」只是展示字段，没有到期判断，不生成待办。
- **待回馈捐赠**：首页只统计数量，不自动生成回馈待办。
- **未到账认领**：只有列表提示和「不能标已回馈」的拦截，不生成待办。

### 4.3 排序与展示

- 「是否逾期」只看每条待办自带的 `overdue` 布尔值，**不与截止日期或今天比较**；只有 t2 初始为 true。
- 待办页：`overdue` 降序，其余按数组顺序（新待办最前）；不按截止日期排序，无「今日/本周」分组或筛选。
- 首页「今日待办」：所有未完成待办，不按日期过滤。
- 详情页「待办」页签：该捐赠人全部待办，含已完成。
- 侧栏无角标，无站内/邮件/推送提醒。

### 4.4 完成与消除

- 点勾选按钮或「完成」打开弹窗：回填结果（非必填）、「同时生成互动记录」复选框（默认勾选，但只有回填结果非空才真正写入时间线）。
- 确认后：`status=已完成`、`overdue=false`，写「完成待办」留痕，页面刷新。
- 完成后从首页消失，进入待办页「已完成」区块；详情页划线显示，按钮变「已回填」。
- 不支持删除、取消、延后、编辑、重新打开、批量完成；完成即终态。
- 完成不会更新捐赠人 `lastContact`，不会关闭承诺，也不会改变捐赠回馈状态。

### 4.5 实现边界

- 90 天自动生成、承诺到期判断、回馈待办生成均未实现。
- 完成待办与捐赠人档案、承诺、统计之间没有回写关系。
- 待办数据仅存内存，刷新还原；ID 用 `'t' + Date.now() % 100000`，理论上可能重复。

## 五、捐赠人门户

### 5.1 外部人员登录后的门户（F-07）

顶部独立导航条：品牌「奇色花 · 捐赠人门户」、标记「捐赠人端」、姓名·单位、退出登录；无管理端侧栏与导航。

1. **概览**：累计支持次数、待反馈数、最近一次月份（按本人记录实时计算）。
2. **我的捐赠与物资去向（只读）**
   - 合并两类数据：该捐赠人的捐赠记录 + 心愿单认领记录（同日期同心愿单去重）。
   - 每笔展示：物品与数量、日期、类型、状态标签（已反馈 / 待反馈 / 未到账）、三步「已接收 → 已分配 → 已使用/反馈」。
   - 示例账号共 3 笔：玩具 50 套（待反馈）、感统器材 ×1 套、美术材料包 ×40 份。
   - 没有任何编辑入口。
3. **提交支持意向**
   - 类型：物资捐赠 / 资金资助 / 志愿服务 / 月捐意向；意向内容必填；可填留言；联系方式预填账号脱敏号码。
   - 内容为空时拦截；提交后显示成功卡片，说明仅本人与机构可见、2 个工作日内联系，可再提交一条。
4. **回馈与报告**
   - 有已回馈记录时列出；当前示例账号没有，显示空状态，不编造内容。
   - 报告按文档 P2 只保留入口，点击弹出规划说明（一页纸汇总、数据不足降级为简短致谢、不编造）；月捐未开放。
5. **申请绑定**
   - 未看到某笔捐赠时可提交绑定申请，弹窗预填本人姓名/单位；提交仅提示“机构核对后绑定”，不接后端。
6. **数据边界**：所有查询按当前账号的 `donorId` 过滤；不出现档案、导入、待办或其他捐赠人信息。

### 5.2 门户通用约束

- 只读，不可修改、删除、导出。
- 不展示他人数据；无跨捐赠人搜索。
- 门户数据来自内存，刷新还原。

## 六、已知问题（按影响排序）

### 6.1 高影响（影响核心承诺或演示可信度）

1. **90 天自动生成待办未实现**：只有统计与标签，没有扫描或生成逻辑；且完成待办不更新 `lastContact`，所以「90 天未联系」永远不会消除。影响：待办中心（F-06）、档案状态、首页统计。
2. **承诺逾期与回馈待办未自动生成**：`overdue` 是静态字段，AI 提取的承诺固定为未逾期；t3 与李静那笔「已回馈」捐赠（n1）自相矛盾。影响：逾期提醒、回馈跟进、演示说服力。
3. **数据导入是纯演示**：不真正读取文件、不写入档案；14 行/8 列、500 行上限、12 成功 1 拒收均为写死。影响：F-02 的“迁移现有表格即可用”叙事。
4. **全部数据仅存内存、时间为硬编码**：刷新即还原；`TODAY`、留痕时间、AI 记录日期固定为 2026-11 月。影响：连续演示与验收。
5. **权限没有真实鉴权**：账号、角色、实名均为前端演示，管理端仅凭前端登录态进入，没有服务端校验或接口级权限控制。影响：隐私口径与真实上线的安全性。
6. **外部门户入口与绑定写死**：只支持一个外部账号，文档提到的“邀请链接”未实现；申请绑定只弹提示。影响：F-07 入口与异常流程的验证。
7. **门户“回馈接收”只有空状态**：示例账号无已回馈记录，报告为 P2 占位。影响：门户完整度观感（文档本身也把报告列为 P2）。
8. **权限页与门户口径并存**：权限页仍把外部人员标为「待定」（指管理端权限），而门户已实现。影响：角色定义需要产品统一说法。

### 6.2 中影响（功能缺口或数据不一致）

9. **分析页建议为写死**：候选建议固定 3 条（含真实姓名），不随数据变化。影响：分析视图的可信度。
10. **待办无去重/合并**：同名档案只提示不合并；重复保存 AI 记录会生成多条同名待办。影响：数据整洁度（F-06 提到的重复合并未做）。
11. **待办能力有限**：无编辑、删除、延后、重开、负责人筛选、搜索、分页、提醒通道。影响：日常使用模拟。
12. **回馈状态语义不统一**：心愿单认领自动生成的记录一律「待回馈」；门户与后台对“已到账未回馈”的展示不完全一致。影响：回馈统计与门户展示。
13. **脱敏仅覆盖政府类拦截**：手机号脱敏是数据层展示，导入/录入的其他敏感字段没有分级或权限控制。影响：F-12 的完整边界。
14. **ID 生成可能重复**：新建档案/待办用 `Date.now() % 100000`，同一毫秒多次创建可能撞 ID。影响：极端操作下的数据错乱。
15. **移动端仅基础适配**：管理端表格横向滚动，外部门户可用；复杂表格在手机上体验一般。

### 6.3 低影响（体验与一致性）

16. 无导出/打印、无数据备份、无空态引导的系统化设计。
17. 通知、批量操作、登录失败次数限制等均未实现。
18. 首页「今日待办」标题与实际“全部未完成”口径不一致。
19. 待办页顶部“自动规则”文案容易让人误以为规则已生效（实际未生效）。

### 6.4 与需求文档不一致或仍待确认

1. **P0 个人捐赠人档案字段表**是文档内嵌的多维表格，本次只读权限未能读取；原型字段为按正文推断。影响：字段口径。
2. **“有效互动”未定义**（电话/微信/见面是否都算）；原型不判断互动有效性。
3. **提醒阈值“暂定 90 天”**未最终确认；原型按 90 天展示。
4. **脱敏边界未定**：政府类整条不入库 vs 保留模糊表述；原型按“整条拦截”。
5. **实名账号可追溯的技术方案待验证**；原型只有界面演示。
6. **捐赠人门户是否本期上线待机构确认**；原型按 P1 简化版实现。
7. **报告周期与用途说法不一**（月度/年度、对外披露/理事沟通）；原型合并为一个 P2 入口。
8. **机构名称与人数口径**：文档标题/正文“奇色花”，需求聚焦段落出现“七色花”；服务对象 350 vs 353、试点园 190 vs 194，文档注明以机构确认为准。原型统一用“奇色花”，不展示具体人数。
9. **判重规则缺失**：同名同单位如何处理；原型只提示不阻断。
10. **现有 Excel 行数与表头未知**；原型使用 8 列 × 14 行示例。
11. **回馈状态没有正式状态机**（未到账 / 待回馈 / 已回馈为原型自定）。
12. **承诺事项与待办、逾期的关系未定义**；原型只有展示字段，不联动。

## 七、未来设想（尚未实现，不属于当前原型逻辑）

> 以下是后续讨论用的机制设想。原型没有对应字段、入口、筛选或审批界面，现有页面行为也不会体现这些规则。

### 7.1 公共待办与个人待办

- **两类待办**：公共待办（所有人可见）与个人待办（仅创建者本人可见）。
- **吴冲（管理员）新建时选择类型**：公共 → 全员可见；个人 → 仅他自己可见。
- **其他成员建公共待办需申请**：不能直接创建，需要向吴冲账号发起申请，由吴冲处理；批准后作为公共待办展示给所有人。
- **尚未明确的细节**：个人待办能否转公共、申请被拒如何反馈、申请是否需填理由、审批是否留痕、外部人员是否参与。

### 7.2 与当前实现的差别

- 当前所有待办在同一个 `DATA.tasks` 数组里，没有 `visibility`（公共/个人）与 `createdBy` 字段，只有 `owner`（执行人）。
- 首页、待办页、详情页展示同一份列表，不做按人过滤：任何进入管理端的机构工作人员看到的待办完全相同。
- 新建待办（手动或 AI）对管理端所有账号一视同仁，没有“只有吴冲能建公共待办”的限制，也没有申请/审批/转换流程。
- 登录只区分机构工作人员与外部人员，管理端内部无身份差异，无法支撑“仅本人可见”。

### 7.3 若要落地，至少需要

1. 待办增加 `visibility`（公共/个人）与 `createdBy` 字段。
2. 列表按当前账号过滤：公共全员可见，个人仅创建者可见。
3. 新建弹窗为吴冲提供类型选择；其他成员默认只能建个人待办，并提供“申请公共待办”入口。
4. 新增申请状态（待审批/已批准/已拒绝）与吴冲的审批界面；批准后转为公共并保留申请记录。
5. 申请与审批动作写入操作留痕。
